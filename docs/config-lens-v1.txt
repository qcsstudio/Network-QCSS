Scope and privacy
-----------------
This is a deterministic, read-only, browser-local configuration explanation tool.
It does not use paid generation, the QCS database, a language-model API, device
credentials, packet probes or automatic configuration deployment.

Select vendor, device family, OS train, optional exact build and export type.
All selected versions describe syntax families, not recommended/current firmware
or exhaustive tested command coverage. The exact build is operator-supplied context,
not proof of the active firmware. Unknown statements are always surfaced.

Included families: Cisco IOS/IOS XE router and Catalyst, NX-OS Nexus, ASA, partial
FTD diagnostic output; FortiGate FortiOS, FortiWeb and standalone FortiSwitch.
FTD running-config is ASA-style diagnostic data and cannot establish the complete
FMC/FDM access-control, Snort, inspection or application policy.

Import accepts UTF-8 CLI text without an application-imposed file-size, line-count
or line-length limit. Available browser memory and device capacity still apply;
this is not a promise to process arbitrarily large input on every device.
Binary/encrypted backups, JSON/XML/YAML and archive files remain rejected.
No supplied text is executed. Files are decoded incrementally inside the local
Web Worker, not copied into a huge textarea. Progress, cancellation and stale-result
invalidation remain available. There is no elapsed-time rejection; after ten seconds
the workspace reports continued processing. A terminated worker never falls back
to a server. Scoped object references use indexed lookup instead of quadratic scans.
Object choices, reference diagrams, settings, source lines and export previews are
paged without discarding input. Long statement text can be expanded in full.

Masking happens before parsing or diagram generation. Known passwords, hashes,
keys, communities, certificates, banners and free-text comments are removed.
Pasted input is replaced with the masked form after successful analysis. A selected
file remains an in-memory File reference for reanalysis until cleared or navigation;
its raw contents are read only in the worker. Source and exports use masked output.
Unknown secret formats, identities and addresses may remain. Downloads require a
human preview/acknowledgment. Masked output is not a restorable device backup.
No raw configuration, result or visitor search is stored in browser storage.

The workspace requires a fresh document to unload previously loaded tracking
listeners. Route-specific CSP blocks third-party scripts and connections. The
existing Clarity allowlist excludes this tool. Browser extensions, compromised
devices, browser caches and saved downloads are outside QCS control; no secure
memory-erasure guarantee is made.

Diagrams show parsed references, never invented cabling or proven packet paths.
References are resolved only within an explicitly represented context. Built-in,
external, missing and unsupported references remain unresolved, not automatically
misconfiguration findings. The engine does not calculate inherited defaults,
effective ACL/NAT precedence, routing convergence or vulnerability applicability.
Counts represent supported statement coverage, not confidence or security scores.

Admin vendor maintenance
------------------------
The authenticated update endpoint accepts no request body or visitor configuration.
Same-origin POST and existing admin session checks are mandatory. It fetches only
allowlisted official Cisco/Fortinet sources, bounds size and duration, validates
redirects, rejects XML entities/DTDs, sanitizes links and never executes feed text.
Public-source results are cached for 30 minutes per process; there is no cron or
background paid service. The admin browser stores only the previous public-source
report for comparison, never customer configurations.

Check vendor updates retrieves PSIRT RSS, Fortinet firmware notices and selected
product documentation. Unavailable sources are reported as unavailable. A successful
fetch or changed document hash does not prove a new firmware version or vulnerability.
Feed notices require original affected-version and feature applicability review.

Download review package saves a JSON evidence snapshot. It does NOT silently update
the production parser. Activation procedure:
1. Review the original release notes/command reference/PSIRT affected-version table.
2. Update src/lib/config-lens/catalog.ts and only the relevant parser/rule modules.
3. Add synthetic or legally supplied sanitized fixtures for the changed syntax.
4. Test positive, unknown, negated, nested, malformed and secret-containing cases.
5. Re-run browser no-transmission, layout/accessibility and admin-auth tests.
6. Review the exact diff and deploy. Never execute remote code or download firmware.
